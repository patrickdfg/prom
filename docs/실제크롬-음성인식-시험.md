# 실제 크롬 음성인식 시험

2026-10-19. 이전 시험결과2~5는 로컬 받아쓰기 참고 시험이다. 이 시험에서는 Windows 실제 Chrome의 Web Speech 결과를 수집한다. 원고 위치 판정 로직은 고치지 않는다.

후속 확인: 직접 입력 네 편은 전체 종료했고 기본 마이크 예약 시험은 3분 23초에 `no-speech`로 중단됐다. 기본 마이크 네 편의 자동 시험이 검증된 상태는 아니다. [분석과 업데이트 지침](실제크롬-분석-업데이트지침-20261019.md)에 실제 결과와 수정 우선순위를 기록했다.

## 두 입력 경로

1. **스피커 → 실제 마이크**: Chrome `SpeechRecognition.start()` 기본 마이크. 휴대폰에서 원본 녹음을 재생하고 PC의 Realtek 마이크로 듣는다. 원고·녹음·중간/확정 인식 결과·시각·원고 위치를 따로 보관한다.
2. **녹음 트랙 → 크롬 인식**: Chrome `SpeechRecognition.start(audioTrack)`. 녹음을 1배속으로 실제 크롬 인식기에 넣는다. 로컬 받아쓰기나 합성 발화를 입력하지 않는다.

설정은 운영 화면과 같은 `ko-KR`, `continuous: true`, `interimResults: true`, `maxAlternatives: 1`이다. 원고 해석·쪽 나눔과 추적 함수는 운영 소스를 그대로 불러 VM에서 실행한다. 따라서 실제 브라우저 스크롤 렌더링을 측정한 영상은 아니다. 음성 인식과 위치 판정의 원시 기록이다.

## 연결 점검에서 확인한 사실

- 실제 목소리를 말한 기본 크롬 마이크 점검은 인식됐다.
- 같은 PC의 브라우저 재생음은 기본 마이크에서 `no-speech`, 인식 0건이 반복됐다. 반향 제거를 끈 별도 마이크 트랙에서도 일부만 인식됐다. PC 음악 앱 재생 점검은 0건이었다. 이 결과만으로 원고 추적 로직 오류라고 판단하지 않는다.
- 휴대폰 재생음은 기본 크롬 마이크로 실제 인식됐다. 최초 휴대폰 점검에서는 선택 원고가 10월 4일이었으나 실제 재생음은 10월 14일이었다. 이 점검은 본시험에서 제외하고, 원시 기록과 불일치를 보존한다.
- 마이크 트랙을 명시적으로 넣는 반향 제거 실험과 기본 마이크 `start()` 시험은 구분한다. 반향 제거 실험을 운영 기본 마이크 결과로 합치지 않는다.

## 자동 수집

```powershell
node tests/chrome_worship_server.cjs <비공개-녹음-폴더> 8767
python tests/chrome_worship_report.py <비공개-녹음-폴더> --watch
```

서버는 `127.0.0.1`에서만 듣는다. 준비된 `manifest.json`, 날짜별 `metadata.json`, `pages.json`, `audio.mp3`가 필요하다. 원본 준비는 기존 `worship_recordings.py` 흐름을 사용한다. 수집 서버는 운영 소스 해시가 준비 시점과 같은지도 확인한다.

날짜별·경로별·실행별로 `metadata.json`, `state.json`, `events.jsonl`, `summary.json`, `timeline.csv`, `기록.md`, `재검토.html`을 저장한다. 마이크 입력을 녹음할 수 있으면 `microphone.webm`도 보존한다. 원고·실제 인식문·음성은 저장소 밖 비공개 폴더에만 둔다.

`complete`만 전체 재생을 마친 기록이다. 연결 점검, 직접 말하기, 부분 중단, 입력 실패를 본시험 완료로 세지 않는다. 원문 끝의 고유한 문자열이 일치할 때만 자동 참고 위치를 붙이고, 일치하지 않는 발화는 판정 유보로 둔다. 참고 위치 집계를 인식 정확도나 전체 추적 성공률로 해석하지 않는다.

```powershell
node tests/chrome_worship_validate.cjs <비공개-녹음-폴더>
```

검증은 저장한 모든 실제 결과의 보존, 시각 순서, 집계, 동일 운영 함수로 재실행했을 때의 위치 일치와 소스 해시를 확인한다.

## 휴대폰 한 번 조작으로 네 편 재생

`tests/worship_speaker.html?start=<UTC-밀리초>`는 공개된 원본 녹음 네 편을 순서대로 재생하는 시험 보조 화면이다. 원고나 마이크 정보를 수집하지 않는다. 휴대폰에서 준비 버튼을 한 번 누르면 예약 시각부터 원속도 재생하며 편 사이에는 30초 여유를 둔다.

PC 시험 화면도 같은 `?start=` 값으로 열고 **휴대폰 예약 재생 네 편 기록**을 누른다. 시작 5초 전에 기본 크롬 마이크를 연결하고 예약 시각에 참조 시계를 시작한다. 각 편이 끝난 뒤 10초 더 받아 마지막 발화를 보존한다. 휴대폰 재생 지연과 두 기기의 시계 차이는 녹음 대조 시 확인해야 한다. 참조 시계만으로 실제 휴대폰 소리의 시작 시각이 완벽히 일치했다고 주장하지 않는다.

휴대폰 화면은 켜 두며 다른 소리나 알림이 섞이면 기록에 남긴다. 화면 잠금 방지는 브라우저가 지원할 때만 적용된다. 기기·브라우저에 따라 준비 후 예약 재생이 막히면 자동 성공으로 처리하지 않는다.

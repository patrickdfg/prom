# 실제 크롬 시험 분석과 업데이트 지침

2026-10-19 KST. 원시 기록을 분석하고 업데이트 우선순위를 정리했다. 이번 작업에서는 운영 음성 추적 코드와 시험 도구의 동작을 변경하지 않았다.

**판단: 추적 판정 기준은 우선 유지한다. 시험의 재생 확인·실패 처리와 앱의 기록 보존을 먼저 개선한다.** 기본 마이크를 통한 네 편 전체 시험은 끝나지 않았으므로, 모든 환경에서 잘 따라온다고 결론 내리지 않는다.

- 나머지 기준점 7건은 10월 11일 **01:00.723~01:01.460**의 한 구간이다. 인식문상 제목을 소개한 뒤 함께 다시 읽는 문맥이며, 모두 중간 결과였다. 읽기 위치는 43자에 유지됐고 참고 위치는 32자였다. 이를 7개의 별도 오작동으로 세거나 자동으로 뒤쪽으로 되돌리는 근거로 쓰지 않는다.

- 관측된 한 번의 최대 전진은 정규화 문자 23자였다. 이번 자료에서는 큰 오이동을 막기 위한 새 임계값을 정할 근거가 나오지 않았다.
- 10월 18일은 이전 로컬 받아쓰기 참고 시험에서 끝 3자 앞에 멈췄지만 실제 크롬 입력에서는 끝까지 갔다. 특정 받아쓰기 결과에만 맞춰 추적 기준을 바꾸지 않는다.

이 비교는 PC 5줄·선행 3자·페이지 모드의 운영 해석/추적 함수를 VM에서 실행한 기록이다. `cueMatch`는 꺼져 있고 `go`·`render`는 화면을 그리지 않는 대체 함수다. 실제 스크롤 화면·전체화면·다음 줄 미리보기·수동 이동·모바일 입력까지 검증한 결과가 아니다.

## 기본 마이크 시험에서 확인한 한계

직접 말한 목소리는 기본 크롬 마이크에서 인식됐다. 같은 PC의 재생음은 0건 또는 일부만 인식됐다. 소리가 필터링되는 정확한 지점은 확정하지 않았다.

휴대폰 점검에서 504건이 들어왔지만 실제 녹음은 10월 14일, 선택 원고는 10월 4일이었다. 이 점검은 입력 연결 확인으로만 사용하고 추적 성능 평가에서 제외한다.

18:15 예약 시험은 31건을 받은 뒤 `no-speech` 16회가 발생하여 **18:18:24에 중단**됐다. 참조 시계는 3분 22.9초, 인식 시작/종료는 각각 20회였다. 원고 위치는 0자였다. 이 기록은 실패한 입력 시험이며 10월 4일 전체 시험 완료가 아니다. 뒤의 세 편도 기본 마이크 본시험이 시작되지 않았다. 현재 자동 마이크 수집이 계속된다고 안내하면 안 된다.

PC에는 휴대폰의 실제 준비·재생·버퍼링·종료 이벤트가 전달되지 않는다. 그러므로 이 로그만으로 휴대폰 조작 실패, 기기 시계 차이, 재생 차단, 마이크 입력 문제 중 어느 것이 원인인지 단정하지 않는다. 공개된 네 음원의 SHA-256은 로컬 시험 사본과 모두 일치했다.

## 업데이트 우선순위

| 순서 | 대상 | 필요한 업데이트 | 근거 |
|---|---|---|---|
| 1 | 시험 도구 | 실제 재생 확인 후 시작, 음원/원고 연결 확인, 실패·미실시 상태 구분 | 예약 시각만 맞춘 시험이 인식 없이 중단됨. 초기 휴대폰 점검은 날짜도 불일치 |
| 2 | 시험 도구 | 저장 실패 시 종료가 멈추는 처리 수정 | 저장 실패를 주입해 자기 큐를 기다리는 상태 재현 |
| 3 | 운영 앱 기록 | 세션 전체 보관 또는 잘린 범위 명시, 원고별 세션 구분 | 현재 메모리 2,000건, 재접속용 저장 600건 한도 확인 |
| 4 | 운영 앱 상태 | 권한 대기·연결됨·실제 인식·원고 불일치를 구분하고 반복 실패 안내 | 연결 표시만으로 실제 말씀 입력을 확인할 수 없었음 |
| 5 | 후속 검증 | 실제 앱 화면에서 기본 마이크·스크롤·수동 이동·모바일 재시험 | 현재 완료 자료는 직접 트랙 입력과 VM 위치 판정에 한정 |

### 1. 시험 시작과 완료 판정

사용자는 준비 버튼을 한 번만 누르게 하되, 내부적으로는 동일한 시험 세션에서 음원 식별자·원고 해시·준비·실제 `playing`·버퍼링·실제 종료를 확인한다. 휴대폰과 PC 사이의 이벤트 전달 방법이 없는 상태에서 시각 예약만으로 자동 연결됐다고 표시하지 않는다.

PC 참조 오디오의 종료를 휴대폰 녹음 종료로 간주하지 않는다. 원본 시작/끝이 실제 입력 음성에 포함되는지 대조하고, 재생이 확인되지 않으면 본시험 미시작 또는 입력 실패로 남긴다. 실패한 기록도 열어볼 수 있게 하고, 종료된 실행을 대시보드에서 '이벤트 수집 중'이라고 표시하지 않는다.

**통과 조건:** 날짜가 다른 음원, 준비하지 않은 휴대폰, 예약 지각, 버퍼링, 중간 정지, 시계 차이를 넣어도 완료로 오인하지 않는다. 정상 재생은 네 편을 원고에 맞춰 분리 보관한다. 실제 인식된 날짜만 보고 운영 원고를 임의로 바꾸지 않는다.

### 2. 저장 실패 종료 처리

`tests/chrome_worship.html`의 `record()` 실패 처리는 `stopCurrent()`를 반환한다. 그런데 `stopCurrent()`는 같은 기록 큐 뒤에 종료 기록을 붙여 기다린다. 실패 처리 중인 큐가 종료를 기다리고, 종료가 그 큐를 기다리는 구조다. 저장 실패 주입에서는 250ms 뒤에도 완료되지 않았다. 점검에서는 종료 대기를 5ms 이하로 단축했으므로 정상 종료 지연 때문이 아니다. 이번 실제 녹음에서는 저장 실패가 관측되지 않았다.

실패한 큐가 정리된 뒤 별도 경로에서 종료하도록 바꾸고, 종료는 한 번만 실행한다. 음성 파일 업로드도 HTTP 성공 여부를 확인한다. 저장하지 못한 자료가 있으면 부분 기록으로 표시하고 복구할 수 있게 보존한다.

**통과 조건:** 이벤트 또는 음성 조각 저장에 실패를 주입해도 종료·오류 안내가 끝나고 완료로 표시되지 않는다. 종료 중 들어온 마지막 결과와 저장되지 않은 자료의 범위를 알 수 있어야 한다.

### 3. 운영 인식 기록 보존

`index.html`의 `VLOG_MAX=2000`, `vlog.slice(-600)`을 그대로 실행해 확인했다. 10월 4일과 같은 7,614건을 넣으면 메모리는 마지막 2,000건, 재접속용 저장은 마지막 600건만 남는다. 이번 시험 도구의 전체 원시 기록은 별도로 보존되어 이 한도 때문에 유실된 것이 아니다.

화면용 최근 기록과 분석용 세션 기록을 분리한다. 전체 기록을 켰다면 브라우저 내부 저장소에 분할 보관하고, 기록 내보내기는 세션·원고 식별자·수집 시작/끝·잘린 수량을 포함한다. 원고를 바꿨을 때 예전 이벤트를 현재 원고와 잘못 짝짓지 않는다. 저장 공간 부족도 알 수 있어야 한다.

시험 도구의 네 편 원시 이벤트만 약 891MB다. 중간 결과마다 전체 누적 인식문을 중복 저장하는 방식을 그대로 운영 앱에 옮기지 않는다. 변경된 결과와 최종 구간을 이용한 재구성 또는 무손실 압축을 검토하되, 재구성한 이벤트·순서·위치가 원본과 같음을 검증한다. 기존 원본은 검증 전 삭제하지 않는다.

**통과 조건:** 최소 40분·12,000건의 한 세션과 원고 교체를 시험한다. 새로고침·저장 실패 이후에도 보존/유실 범위를 정확하게 내보내고, 조용히 앞부분을 잘라 전체 기록처럼 표시하지 않는다.

### 4. 입력 상태와 반복 연결

연결됨, 소리 크기 감지, 실제 글자 인식, 원고 위치 일치를 별개 상태로 다룬다. 마이크 권한을 기다릴 때부터 현재 상태를 표시하고, 늦게 연결된 마이크를 사용자가 이미 중지했다면 즉시 해제한다.

현재 PC는 인식 종료 후 즉시 재연결하며 연속 무발화 횟수 제한은 Android에만 있다. PC의 반복 실패에는 유효 인식 시각·오류 종류를 기준으로 안내와 재연결 간격 조절을 검토한다. 조용한 설교 구간만으로 원고를 넘기거나 장치 권한을 반복 요청하지 않는다. 강제 중지/재개 정책은 긴 침묵 후 다시 읽는 시험을 통과한 뒤 결정한다.

기존 조작줄과 인식 상태 안내를 활용한다. 사용자가 없애 달라고 한 설교 전 점검 화면을 다시 만들지 않고, 읽기 전체화면에 진단 UI를 겹쳐 놓지 않는다. Android의 시작음 감소용 말소리 대기 정책은 이 Windows 기록만으로 되돌리지 않는다.

## 이후 작업에 사용할 지침

1. 각 발견을 실제 로그 관측, 코드 점검, 실패 주입 재현, 아직 검증하지 못한 추정으로 구분한다.
2. 먼저 시험의 재생 확인·실패 처리를 고쳐 유효한 기본 마이크 네 편을 확보한다. 입력이 없거나 원고가 다른 기록으로 추적 임계값을 바꾸지 않는다.
3. 운영 앱의 기록 보존과 상태 안내를 독립적으로 개선한다. 다음 검토 때 원고 전체 구간을 분석할 수 있어야 한다.
4. 추적 알고리즘은 실제 녹음의 시각·당시 인식문·원문 위치로 반복 재현되는 오류가 있을 때만 바꾼다. 이번 네 편을 회귀 자료로 유지하고 재독·생략·부연 설명·중간 결과 수정·긴 침묵·수동 이동을 함께 검증한다.
5. 수정 전후의 같은 입력을 비교하고, 확인 가능한 기준점과 판정 유보를 분리한다. 한 줄 이내 비율을 전체 정확도로 발표하지 않는다.
6. 운영 변경은 시험 도구 변경과 구분해 검토한다. 원고·음성·인식문은 비공개로 유지하며 공개 저장소에는 방법·집계·지침만 올린다.

전체 원시 이벤트의 집계·시각 순서·소스 해시·동일 함수 재실행 위치 검증은 종료된 18개 실행에서 통과했다. 이 중 정상 종료한 직접 입력 본시험은 위 네 편이다. 개인 원고와 인식문을 포함한 상세 분석·실패 주입 증거는 로컬 시험 폴더에 보관한다.

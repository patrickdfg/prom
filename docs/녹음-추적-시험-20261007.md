# 10월 7일 수요말씀 녹음으로 음성 추적 시험

시험일: 2026-10-19. 기준 코드: `7edba0d`.

## 자료와 방법

- 사용자 첨부 `261007 수요말씀.hwp`와 `patrickdfg/malsseum`의 `audio/1007.mp3`를 사용했습니다. 녹음 길이는 21분 26초입니다.
- 현재 PROM의 실제 HWP 해석·쪽 나누기 코드를 실행했습니다. PC 5줄 기준 92쪽이며, 음성 대조용 본문은 공백·문장부호·메모 등을 제외한 2,814자입니다.
- 녹음 전체를 로컬 `faster-whisper base`로 받아썼습니다. 221개 구간, 1,546개 단어를 시간 순서대로 기존 `onHeard`에 공급했습니다. 크롬 인식 서버에 녹음을 전달한 시험은 아닙니다.
- 전체 원고와 전체 받아쓰기를 별도로 정렬해, 원고에서 유일하게 일치하는 12자 이상 구간 75개를 기준점으로 삼았습니다. 각 입력의 끝이 기준점 안에서 10자 이상 일치할 때만 정확한 위치 점수를 계산했습니다. 기준점의 총 길이는 본문 2,814자 중 2,062자입니다.
- 반복·부연 설명·생략·오인식 시험은 같은 원고의 앞·중간·뒤 세 위치에서 합성했습니다. 합성한 오인식은 이 녹음에서 크롬이 실제로 낸 오류라는 뜻이 아닙니다.
- 원고·녹음 사본·받아쓰기·정답 위치·상세 실행 결과는 로컬에만 보관합니다. 이 문서에는 본문을 인용하지 않습니다.

## 비교한 보완안

브라우저용 기능 코드는 바꾸지 않고, 재생 시험 도구에만 두 가지 실험을 넣었습니다.

### 1. 임시 인식의 큰 이동 보류

120자 넘는 이동이 임시 결과에서 나왔으면 현재 위치를 유지하고 확정 결과를 기다립니다. 가까운 줄을 따라가는 기존 동작은 그대로 둡니다.

- 합성한 임시 오인식 3건에서 잘못된 이동을 모두 막았습니다.
- 실제로 300자를 생략한 비교 사례는 다음 확정 입력에서 정상 복귀했습니다.
- 이 시험에서는 인식 결과 한 번, 설정한 입력 시각으로 약 2초를 더 기다렸습니다. 실제 크롬의 확정 간격은 다를 수 있습니다.

우선순위가 높은 보완 후보입니다. 현재 코드는 확정 여부(`fin`)를 기록하지만 위치 판정에는 사용하지 않습니다.

### 2. 큰 생략 뒤 위치 재탐색

기존 추적이 멈췄을 때만 앞으로 1,400자 이내를 추가로 봅니다. 원고 전체에서 유일한 36자 이상 정확한 문구가 있고, 12초 안에 이어지는 위치가 한 번 더 확인될 때 복귀시키는 실험입니다.

- 500자 생략 시험의 3구간 모두 복귀했습니다. 기존에 멈춘 2구간도 복귀했습니다.
- 이 실험만으로는 임시 오인식에 따른 이동을 막지 못했습니다. 첫 보완안과 함께 검토해야 합니다.
- 반복되는 문구·여러 번 설명 후 복귀·서로 다른 원고에서도 추가 검증이 필요합니다.

두 실험을 함께 적용한 재현에서는 29개 시나리오 모두 목표 끝 위치로 도달했고, 합성한 임시 오인식 3건에서도 잘못 앞서가지 않았습니다. 같은 녹음의 확인 지점 결과도 유지됐습니다. 시험용 조건에서 얻은 결과이며 운영 코드에 반영한 상태는 아닙니다.

## 재현 도구

`tests/recording_replay.cjs`는 외부의 비공개 입력 파일을 읽습니다.

```text
node tests/recording_replay.cjs prepare <HWP의-OLE-스트림.json> <페이지.json>
node tests/recording_replay.cjs replay <시험입력.json> <결과.json>
node tests/recording_replay.cjs replay <시험입력.json> <결과.json> combined
```

시험 입력은 `pages`와 `scenarios` 배열입니다. 각 시나리오는 `name`, `events`, 선택 항목 `scroll`, `targetEnd`를 가집니다. 각 이벤트는 `time`(초), `text`(그 인식 세션의 누적 글), 선택 항목 `carry`(이전 세션의 마지막 글), `expected`(대조용 본문에서 읽은 글자 수), `reset`(수동 이동), `final`(합성한 확정 여부)을 가집니다. `sourceCommit`과 `reference`에 버전과 정답 위치 산출 방법도 기록합니다.

도구의 `combined`, `confirm-interim`, `bounded-recovery`는 비교용 모드입니다. 실제 사이트 기능을 바꾸지 않습니다. 준비 단계는 OLE 스트림 읽기만 어댑터로 제공하고 실제 HWP 레코드 해석과 페이지 생성 코드를 사용합니다. 재생 단계는 마이크 연결과 화면 그리기를 대신해 실제 음성 위치 판정 함수를 실행합니다.

기존 `speech_follow.cjs`, `speech_match_handlers.cjs`도 통과했습니다.

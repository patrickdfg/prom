# 실제 예배 원고·녹음의 추적 기록 방법

시험결과2~5는 실제 녹음의 발화 순서와 시각을 유지한 기록입니다. 원고 문장을 추가하거나 음성을 고쳐 넣지 않았으며, 생략·오인식 상황도 인위적으로 만들지 않았습니다. 시험결과1의 합성 시나리오·보완안 실험과 구분합니다.

## 고정한 조건

- 추적 코드 기준 버전: `49cbf97`. 운영 코드와 판정 로직은 변경하지 않습니다.
- 원고: 사용자 제공 HWP. 현재 사이트의 HWP 해석·쪽 나누기 코드를 그대로 실행합니다.
- 음성: `patrickdfg/malsseum`의 해당 날짜 녹음 전체. 재생 속도·음량·발화 순서를 바꾸지 않습니다.
- 받아쓰기: 로컬 `faster-whisper base`, 한국어, CPU int8, 단어별 추정 시각, VAD 사용. 원고를 힌트나 정답 요청문으로 넣지 않습니다.
- 입력: 받아쓴 모든 단어를 원래 시각 순서대로 누적해 현재 `onHeard`에 전달합니다. 수동 위치 보정이나 중간 재시작으로 결과를 도와주지 않습니다.
- 표시 조건: PC 5줄, 한 장 보기, 넘김 3자. 다음 장 첫 줄 기능과 괄호 제외는 사용하지 않습니다.
- 인식 세션은 45초 단위, 이전 세션 끝 60글자를 넘겨주는 것으로 재현합니다. 이는 비교를 위해 고정한 연결 조건이며 실제 크롬의 종료·재연결 시각을 측정한 값은 아닙니다.

받아쓰기는 녹음 전체를 입력으로 처리하지만 무음은 VAD가 거르고, 실제 발화를 틀리게 받아쓸 수도 있습니다. **크롬 마이크의 실제 인식 이벤트를 수집한 시험은 아닙니다.** 화면 애니메이션·기기 마이크·네트워크 지연·모바일 알림음도 이 기록만으로 판정하지 않습니다.

## 기준점과 판정 유보

전체 받아쓰기와 전체 원고를 별도로 정렬합니다. 원고에서 유일하게 일치하는 12자 이상 구간을 기준점으로 선택하고, 그 안에서 10자 이상 일치한 단어 끝의 위치만 비교합니다. 자동 기준점이므로 사람이 청취해 확정한 정답과는 구분합니다.

- **기준점 한 줄 이내**: 읽은 위치와 자동 기준점이 같은 줄 또는 한 줄 차이입니다.
- **두 줄 차이**: 추적 위치가 기준점보다 두 줄 뒤입니다.
- **지연 후보**: 기준점보다 세 줄 이상 뒤입니다.
- **앞섬 후보**: 기준점보다 두 줄 이상 앞입니다.
- **재독 가능**: 앞서 원고와 정확히 일치한 24자 이상 고유 문구가 나온 뒤 앞의 대목을 다시 읽은 것으로 보입니다. 의도적인 위치 유지일 수 있어 앞섬 오류로 단정하지 않습니다.
- **원문 위치 판정 유보**: 확실한 자동 기준점이 없는 입력입니다. 원고에 없는 설명·인식 오류·반복·기도·무대 음성 등일 수 있으며 성공이나 실패로 계산하지 않습니다.

지연·앞섬 후보가 세 번 이상 이어지고 3초 이상 지속된 구간은 따로 모읍니다. 기준점이 없는 입력도 모두 원래 기록에 남깁니다. **후보 구간은 확정 오류가 아니며** 실제 음성과 원문을 함께 확인한 뒤 원고 생략, 재독, 받아쓰기 오류, 추적 문제를 나눠야 합니다. 한 줄 이내인 입력 비율을 전체 음성 인식 정확도로 부르지 않습니다.

읽은 위치와 표시 쪽을 따로 기록합니다. 쪽 끝에서 3자 먼저 넘기는 설정 때문에 표시 쪽이 읽은 줄보다 먼저 바뀌는 정상 동작을 잘못된 이동으로 세지 않습니다.

## 편별로 보관하는 파일

각 날짜 폴더를 독립적으로 만들고 다음 자료를 로컬에 저장합니다.

| 파일 | 내용 |
| --- | --- |
| `source.hwp`, `audio.mp3` | 시험에 사용한 원고·음성 원본 사본 |
| `metadata.json` | 원본 경로·SHA-256·코드 식별값·음성 저장소 버전 |
| `pages.json` | 실제 변환된 쪽·줄과 대조용 본문 |
| `transcript.json` | 전체 받아쓰기, 구간·단어 시각, 인식 신뢰도와 설정 |
| `reference-private.json`, `fixture.json` | 자동 기준점과 재생 입력 전체 |
| `timeline.csv` | 모든 단어의 시각·발화·원문·판정·이동 전후 위치·쪽·줄 |
| `replay.json`, `summary.json` | 상세 실행 결과와 집계 |
| `기록.md`, `재생검토.html` | 편별 요약·확인할 시각과 원본 음성을 재생하는 로컬 검토 화면 |

원고·받아쓰기·발화별 원문은 공개 저장소에 넣지 않습니다. 공개 기록에는 날짜·집계·확인할 시각과 해석만 남깁니다. 저장한 사본은 원본과 해시가 같은지 확인합니다.

재현 도구는 `tests/worship_recordings.py`와 `tests/worship_replay.cjs`입니다. 외부의 비공개 작업표에 원고·음성·결과 폴더를 지정하고 준비 → 전체 받아쓰기 → 기준점 생성 → 재생 기록 순서로 실행합니다. 코드 해시가 준비 시점과 달라지면 기록을 중단합니다.

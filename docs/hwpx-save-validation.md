# 2026-10-29 저장 형식 목록과 HWPX 내보내기

## 동작

- 상단 `저장`을 누르면 `PPT 저장`, `HWPX 저장`, `프롬프터 저장` 목록을 연다. 기존 PPT 내보내기와 JSON 저장은 각 항목으로 옮겼다.
- HWPX는 현재 화면의 글자·줄바꿈·쪽 나눔·빈 줄·강조·원고 쪽번호·목록 번호·문단 시작 표시를 문서에 기록한다. 현재 검정/흰색 모드와 하늘 그림 배경, 글자색을 보존하며 다시 불러올 때 배경도 복원한다. 위쪽 여백은 10mm다.
- 페이지마다 현재 줄 수에 해당하는 문단을 배치하고 쪽 나눔을 명시한다. 가로 210mm·세로 118mm이며, 5/6/7줄의 글자 크기와 줄 간격을 각각 맞춘다.
- 한/글 2024로 생성한 빈 문서의 표준 패키지를 사용했다. 사용자 이름·기존 날짜·빈 미리보기 그림을 제거했고 원고나 사용자 파일을 템플릿에 넣지 않았다. 외부 서버로 문서를 업로드하지 않는다.
- 내보낸 문서는 표준 문단·글자 스타일에 줄 수와 표시 종류를 기록한다. 다시 불러올 때 현재 본문 XML에서 읽으며 별도의 오래된 원고 사본을 복원하지 않는다. 일반 HWPX는 기존 가져오기 경로를 유지한다.
- 프롬프터 저장(JSON)은 편집 복원용이며 기존 동작을 유지한다. HWPX/PPT 내보내기는 프로젝트의 저장 여부나 현재 편집 상태를 바꾸지 않는다.

## 2026-10-29 하늘 배경과 위쪽 여백 보완

- 하늘 배경을 문서에 포함하고 한글에서 다시 저장한 뒤에도 그림과 10mm 위쪽 여백이 보존되는 것을 확인했다. 저장한 HWPX를 프롬프터로 다시 열면 하늘 배경을 복원한다.
- 5/6/7줄 위쪽 여백, 기존 HWPX·프롬프터 저장 재가져오기 및 실제 원고 5줄·11쪽을 검사했다. 한글 PDF 출력으로 하늘 배경과 글자 표시를 확인했다.

## 재현과 결과

수정 전에는 HWPX 읽기만 지원하고 HWPX 저장과 저장 형식 목록은 없었다.

- `tests/save_hwpx_browser.cjs` 통과: 세 가지 목록, 목록에서 방향키로 쪽이 넘어가지 않음, Esc 닫기, 5/6/7줄과 두 쪽, 빈 줄·공백·XML 특수 문자·강조색·빨간 쪽번호·작은 목록 번호의 저장/재가져오기, 검정/흰색 모드 복원, 일반 HWPX 가져오기, 본문 XML 수정 반영, 편집 중 HWPX/JSON 저장, 저장 창 취소와 원본 보존.
- `tests/save_pptx_browser.cjs` 통과: 새 목록을 통해 기존 PPT 저장이 동작한다.
- 실제 2026-10-27 HWP를 가져와 5줄·11쪽 HWPX로 저장하고 다시 불러왔다. 원본 페이지 배열의 글자·색상·빈 줄·쪽 경계·문단 시작 표시가 모두 동일했다.
- 설치된 한/글 2024에서 시험 파일을 직접 열었다. 5/6/7줄 시험은 각각 2쪽, 실제 원고는 11쪽이었다. PDF 출력과 HWPX 재저장이 모두 성공했다.
- 한/글이 다시 저장한 네 파일도 브라우저로 다시 읽어 글자·색·줄·쪽·문단 시작 표시가 같은지 확인했다. 한글 PDF에서 실제 원고 1쪽·8쪽과 7줄의 강조/쪽번호/작은 번호가 읽기 좋게 표시됨을 확인했다.
- 문법 검사, ZIP의 첫 항목/비압축 `mimetype`, XML 파싱, 문서 내부 참조와 `git diff --check`를 확인했다.
- 기존 원고 페이지 분할, 의미 단위 줄바꿈, 안전한 음성 추적, 선택 발화, PPT 원본 재현 관련 시험도 통과했다. 저장소의 기존 편집기 정규식 시험 `tests/continuous_editor_boundaries.cjs`는 수정 전 커밋 `32c72e0`에서도 같은 `P=pages;...` 문자열 기대 실패를 재현했다. 해당 기존 코드/시험은 변경하지 않았다.

실제 마이크와 물리 OBS/외부 모니터 송출은 이번 저장 기능의 시험 범위가 아니다. 다른 한글 버전 또는 다른 PC의 글꼴 대체 결과는 별도로 검증하지 않았다.

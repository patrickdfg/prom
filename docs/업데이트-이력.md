## 2026-10-31 · 배경그림 가져오기에 사용자 배경 6종 추가

- 갈색 금빛 이중 테두리, 연금빛 장식선 테두리, 흰빛 하늘색 금빛 번짐, 베이지 대리석 밀 이삭·꽃, 청록 대리석 흰 꽃, 분홍 대리석 장미를 공통 배경 보관함에 추가했다. 방송용 PPT 편집과 PPT 만들기 마스터가 같은 목록을 쓴다.
- 여섯 장 모두 1920×1080(16:9)이다. 1·2번 원본(약 1.4:1)은 모서리 테두리와 가운데 장식 문양을 같은 비율로 키우고 직선 구간만 가로로 늘려 문양이 찌그러지지 않게 했다. 3~6번은 원래 16:9라 비율 변경 없이 확대·축소했다. 1~3번은 원본 해상도가 낮아(약 480×340, 736×414) 100% 확대하면 선과 빛이 다소 부드럽다. 5번 원본 맨 윗줄의 1~2픽셀 검은 선은 이웃 줄로 덮었다.
- `ppt/images/library/v6/`의 새 파일과 새 ID로 등록했고 기존 항목과 이미지·사용자 저장 템플릿은 건드리지 않았다. 카탈로그 version 8, 스크립트의 `?v=` 문자열을 올려 새로고침 시 새 목록을 받는다. 선·문양 그림은 PNG, 나머지는 JPEG(장당 150~320KB)이다.
- 검증: 실제 브라우저(로컬 서버)에서 목록에 기존 15장 뒤로 6장이 보이고 썸네일 깨짐이 없음, 한 장씩 골라 적용하면 슬라이드 전체(0,0,960,540)에 1920×1080 그림이 들어가고 원본 파일과 바이트가 같음, 내보낸 PPTX 안 미디어가 1920×1080이며 다시 불러와도 같은 그림, 새로고침 후 자동 저장 복원에서도 유지됨을 확인했다. `image_library`·`image_library_prune`·`editor_media`·`layout_masters` 시험 통과. 저장소의 Node 시험 79개 중 실패 23개는 수정 전과 동일한 기존 실패이다. playwright 기반 `*_browser.cjs` 시험은 이 PC에 playwright가 없어 실행하지 못했다.

## 2026-10-24 · 배경그림 가져오기에 사용자 배경 7종 추가

- 빈티지 베이지 큰 박스, 수채화 파랑·베이지·민트·분홍 잎사귀, 노을빛 핑크 큰 박스, 블루퍼플 큰 박스를 공통 배경 보관함에 추가했다. PPT 만들기 마스터와 방송용 PPT 편집에서 같은 목록으로 선택한다.
- `ppt/images/library/v3/`의 새 파일과 새 ID로 등록했다. 크기·색·그림은 바꾸지 않았고 원본과 복사본 SHA-256이 일치한다. 기존 17개 항목과 이미지 파일을 유지하여 총 24개(배경 9개·그림 15개)가 됐다. 사용자 저장 템플릿을 자동으로 바꾸지 않는다.
- 카탈로그와 불러오는 스크립트의 버전을 올려 새로고침 시 새 목록을 받는다.
- 검증: 24개 이미지의 실제 읽기와 등록 크기 일치, 기존 카탈로그 17개 보존, 새 7개 브라우저 썸네일 정상 로딩을 확인했다. 보관함 분류·중복 제거·원본 보존, 그림 편집 및 편집 이동 회귀 시험과 문법 검사가 통과했다. 로컬 시험 원본에서 Make 마스터의 선택·적용·저장·재선택 복원과 방송용 편집의 선택·적용·저장 및 PPTX 내보내기를 확인했다. 내보낸 PPTX 안에 새 배경 PNG가 바이트 단위로 동일하게 들어가고 원고 연결 2개가 보존됐다. 배포 때 기존 기본 템플릿을 덮어쓰지 않는다. 실제 마이크·물리 송출·드라이브 동기화는 이번 변경 범위 밖이다.

## 2026-10-24 · 초록 말씀의 화자 및 잠언 레이아웃 구분

- 일반 설교의 초록색 구간에만 전체화면 화자 분류를 적용한다. 파랑은 기존 하단 2줄, 검정은 원고 전문으로 유지한다. 검정색으로 적힌 「성령님 말씀입니다」「하나님은」「예수님은」 등의 소개는 화자 판별에만 사용하고 자막 본문에 넣지 않는다.
- 단순히 먼저 등장한 이름보다 실제 말씀하신 화자의 소개를 우선한다. 한 초록 구간 안에서 성령님·하나님 등의 인용 화자가 바뀌면 별도 화면으로 분리하고, 같은 인용의 다음 문단은 화자를 이어받는다. 일반 설명이나 다른 원고로 넘어가면 앞 화자를 이어 쓰지 않는다. 함께 열거한 여러 이름만으로 화자를 단정하지 않는다.
- 연속 번호 잠언은 화자 이름보다 잠언 레이아웃이 우선이다. 「잠언」 제목 아래의 번호 항목은 하나뿐이거나 중간 번호부터 시작해도 잠언으로 처리한다. 잠언 제목이 없는 일반 원고의 고립된 번호는 기존처럼 자동 잠언으로 확정하지 않는다. 원고+완성 PPT의 레이아웃 학습도 괄호·원문자·전각 번호를 같은 기준으로 분류한다.
- 편집창 레이아웃 목록에서 잠언 항목이 빠져 있던 문제도 수정했다. 옛 템플릿에 잠언 키가 없으면 기존 인물 없는 말씀 서식의 별도 사본을 만들어 독립적인 「잠언 항목」으로 편집할 수 있게 한다. 이미 저장한 잠언 디자인은 우선 보존하고, 원본 템플릿·그림을 덮어쓰지 않는다. 사용자가 고른 특정 화자 레이아웃도 서식 재적용 시 유지한다.
- 재현 및 검증: 실제 10/4 주일 원고에서 성령님 소개 뒤 인용문이 일반 말씀으로 나오던 문제와, 예수님·하나님·선생님 소개 누락을 확인했다. 수정 후 해당 원고의 31개 하단 자막은 그대로이고 전체화면은 하나님 2·성자 1·성령 1·선생님 1·일반 2장으로 구분됐다. 본문·색·원고 연결 위치 보존을 확인했다. 나머지 10/11·10/18·10/14 파일은 색상/번호 자막 대상이 없어 기존과 동일하게 자동 생성 대상이 없었다.
- 시험: 화자 안내·같은 문단 앞 검정 소개·혼합 인용 분리·화자 유지/해제·잠언 우선·단일 잠언·번호 형태·원고 연결·레이아웃 사본/그림 보존·수동 선택 보존을 포함한 관련 시험 13개와 문법 검사가 통과했다. 브라우저에서 색상 원고 가져오기 → 6장 생성 → 성령/잠언 편집 선택 → 잠언 적용·저장 → PPTX 다운로드를 확인했다. 내려받은 파일의 실제 레이아웃 순서는 성령·하나님·잠언·잠언·성령·하나님이며 원고 연결 6개와 전용 잠언 서식이 보존됐다. 실제 마이크 및 물리 모니터 송출은 이번 변경의 검증 범위가 아니다.

## 2026-10-24 · 주일설교와 주일예배 전체의 선택 자료 분리

- 기본 주일설교는 말씀 원고만 처리한다. 광고·교독문 입력칸을 숨기고 이전 템플릿에서 남은 입력이나 광고 연결 정보가 있어도 설교 제작을 막지 않는다. 빈 광고 연결 정보가 있는 템플릿에서 광고 없이 제작하면 중단되던 현상을 수정 전 재현했다.
- 새 기본 주일예배 전체 템플릿은 기존 주일설교 디자인을 그대로 사용하며 교독문·광고를 별도 선택 입력으로 받는다. 비운 항목은 예전 문구를 재사용하지 않고 생략한다. 말씀만, 말씀+광고, 말씀+교독문, 세 자료 모두, 광고만, 교독문만 제작할 수 있다. 아무 자료도 없을 때만 입력 안내를 표시한다.
- 기존 예배 전반 템플릿의 제목·성경본문 교체와 예배 순서는 유지한다. 교독문·광고를 생략하거나 새 내용으로 바꿀 수 있고, 광고 양식이 없으면 선택한 템플릿의 말씀 화면 서식으로 추가한다. 사용자가 저장한 템플릿·이름·배경그림은 덮어쓰지 않는다.
- Make와 방송용 PPT가 같은 제작 엔진을 사용한다. 교독문과 광고는 설교 원고와 음성 추적 위치에 섞지 않고 수동 송출 화면으로 둔다. 선택 자료의 원문도 전환 프로젝트와 PPTX 내부 자료에 보관한다.
- 검증: 실제 공통 제작 엔진의 선택 자료 조합·오래된 광고 연결 정보·제목/성구만 있는 원고·본문 및 원고 연결 보존·템플릿 무변경 시험, 기본 템플릿 추가 시 기존 그림/편집 보존 시험을 통과했다. 내용 규칙·자동 인식·같은 원고 재현·Make 전환/백업·레이아웃 이름·광고 양식·여러 원고 입력·편집 이동·그림 편집 회귀 시험과 문법 검사도 통과했다. 브라우저에서 광고 없는 주일설교 생성, 선택 자료 없는 예배 전체 생성, 교독문·광고 포함 생성, 실제 PPTX 다운로드 및 파일 내부 4장/원고 연결/본문을 확인했다. 물리 모니터 송출과 실제 마이크는 이번 변경의 검증 범위가 아니다.

## 2026-10-24 · PROM 문단 경계와 번호 줄바꿈

- 국방 교육.hwp에서 빈 줄로 나뉜 다음 문단이 앞 페이지에 섞이고, 직접 쓴 `1.`·`2.`가 한 줄 또는 페이지 끝에 따로 놓이는 현상을 수정 전 재현했다.
- PC 페이지 구성은 문단 경계를 넘지 않는다. 명시적인 쪽 나누기도 보존한다. `<소제목>` 뒤 빈 줄은 바로 뒤 본문과 이어 제목만 있는 페이지를 피한다. 긴 문단 안에서는 기존 문장·줄 수 기준 분할을 유지한다.
- 문단 첫 번호와 첫 단어를 한 줄 단위로 묶는다. 한글 자동 번호와 직접 입력한 `1.`·`1)`·`①`에 적용하고, 문장 중 숫자·날짜·소수점·색·원고 쪽 표시를 보존한다. 모바일 문단 간격과 기존 저장 JSON을 자동 변경하지 않는다.
- 검증 통과: 새 `tests/manuscript_pagination.cjs`의 최소 재현 사례와 실제 HWP 5편(국방교육, 10/4·10/11·10/18 주일, 10/14 수요)을 각각 5·6·7줄로 검사했다. 국방교육은 5줄 60쪽이며 브라우저에서 실제 파일 불러오기 → 시작 → 여러 장 보기로 번호와 문단을 확인했다. 문단 표시·저장/재열기, 여러 장 보기, 스크롤 시작·설정, 두 화면 이동의 기존 단위시험 5개 및 인라인 문법 검사도 통과했다.
- 기존 보조시험 제한: `cue_spacing.cjs`는 바뀐 송출 도구까지 실행하면서 document 대역이 없어 중단되고, `scroll_slides.cjs`는 현재 연속 스크롤에 필요한 DOM 대역과 맞지 않아 중단된다. 해당 송출·스크롤 파일은 이번 수정 대상이 아니다. `tts_line_follow.cjs`는 Playwright 의존성이 없어 실행하지 못했다. 실제 마이크·음성 서버·물리 송출은 이번 검증 범위가 아니다.
- 사용자 원고·녹음·템플릿은 저장소에 추가하거나 덮어쓰지 않았다. 새 규칙은 원본 원고를 다시 불러올 때 적용한다.

### 최근 반영된 내용

- 스크롤 보기에서 현재 쪽뿐 아니라 화면에 보이는 줄 전체를 대상으로 읽는 위치를 찾습니다.
- 여러 줄을 건너뛰어 읽으면 이동 거리에 맞춰 빠르게 따라갑니다. 3쪽 이상 건너뛰거나 화면 두 개 높이보다 멀리 이동하면 바로 해당 위치를 표시합니다.
- 읽지 않는 설명 줄을 건너뛴 경우, 앞쪽 450자 안의 충분히 긴 고유 문구를 근거로 위치를 찾습니다.
- 괄호 안 내용이나 성경 본문의 일부를 생략하고 읽을 때도 이어지는 원고 위치를 찾도록 보완했습니다. 짧거나 반복되는 문구만으로는 멀리 이동하지 않습니다.
- 마이크를 켠 일반 창에서는 하단 조작줄을 표시합니다. 단독 전체화면의 원고 전용 표시는 유지합니다.
- 음성 인식 기록에 들은 글자·이동 위치·판정과 크롬 결과의 확정/임시 여부(`fin`)를 남깁니다. 기록은 더보기의 "인식 기록 저장"으로 파일로 받습니다. 구글 드라이브 자동 저장은 2026-10-20에 없앴습니다. 대신 시작 화면에서 구글 로그인하면 「저장」한 프롬프터 파일이 드라이브 "설교 프롬프터" 폴더에도 같은 이름으로 올라가고, 다른 컴퓨터에서 로그인하면 그 목록에서 바로 엽니다.
- 실험실의 숫자·장절 인식 및 애드리브 복귀 보강 옵션을 제거하고 기본 음성 추적을 사용합니다. 반전·긴급 안내·구간 반복·연습 녹음은 유지합니다.

음성 위치 판정의 자세한 규칙은 [음성 따라가기 지침](음성따라가기-지침.md)을 참고하세요.

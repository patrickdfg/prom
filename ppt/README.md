# 설교 자막 송출

`https://patrickdfg.github.io/prom/ppt/`

기존 PROM과 분리된 조작창 및 자막 송출창입니다. 원고 전문을 따라가다가 연결된 PPTX 자막 구간에서만 해당 슬라이드를 표시하고, 나머지 구간은 `#00ff00` 녹색으로 표시합니다.

## 사용 순서

1. HWP/HWPX/DOCX/TXT 원고를 불러옵니다. 기존 PPTX를 불러오거나 ‘자막 PPT 만들기’로 새 자막을 생성합니다.
2. 오른쪽 연결 결과를 확인합니다. 정확히 일치하는 자막은 자동 연결합니다. 반복 문장·유사 문장은 ‘확인 필요’, 찾지 못한 자막은 ‘미연결’로 두며 자동 송출하지 않습니다.
3. 확인이 필요한 자막을 선택하고 왼쪽 원고의 시작·끝 줄을 지정한 뒤 ‘연결 저장’을 누릅니다. 한 줄 안에서 일부 문장만 연결한 자동 구간도 원래 문자 위치를 유지합니다. 수동 연결은 지정한 줄 전체를 사용하므로 겹치는 구간은 허용하지 않습니다.
4. ‘송출창 열기’로 별도 창을 열고 원하는 모니터로 옮깁니다. 화면을 클릭해 전체화면으로 전환합니다.
5. 조작창에서 ‘자동 송출’을 켜고 마이크를 시작합니다. 원고를 클릭하면 추적 위치를 다시 지정할 수 있습니다.

자동 송출 중 연결된 자막 카드를 누르면 원고 위치도 해당 구간으로 이동하며 자동 추적을 유지합니다. 미연결 카드를 누르거나 녹색 화면(G), 선택 자막 송출, 이전·다음 자막을 사용하면 수동 유지 상태로 전환합니다. 자동 송출을 다시 켜면 현재 원고 위치로 돌아갑니다. 음성으로 이전 문장의 마지막 글자까지 인식되면, 다음 연결 자막이 첫 글자를 읽기 전에 표시됩니다. 다음 구간이 일반 본문이면 녹색으로 전환합니다. 음성 인식 자체의 지연은 남습니다. 자막은 200ms 동안 부드럽게 나타나고 사라지며 다음 자막은 이전 자막의 퇴장을 기다리지 않고 바로 나타나기 시작합니다. 음성 일치가 8초간 없거나 송출창이 조작창과 8초간 연결되지 않으면 녹색으로 전환합니다.

작업은 IndexedDB에 자동 저장되며 JSON 작업 파일로 내보내기/가져오기를 지원합니다. 불러온 원고, PPT 및 작업 파일을 서버에 업로드하지 않습니다. 브라우저 음성 인식은 브라우저 제공자의 온라인 서비스를 사용할 수 있습니다.

## 지원 범위

PPTX 실제 슬라이드 순서, 마스터/레이아웃 배경, 정적인 그림, 텍스트 자리표시자 위치, 글꼴·색상·굵기·줄바꿈을 읽습니다. PowerPoint 프로그램을 실행하는 방식이 아닙니다. 설치되지 않은 글꼴은 대체되며 차트, 표, 애니메이션, 일부 복잡한 그룹 변형·이미지 효과는 정확히 재현되지 않을 수 있습니다. 가져오기 경고와 송출 미리보기를 확인하세요. 구형 `.ppt`는 `.pptx`로 변환해야 합니다.

음성 인식은 한국어 브라우저 인식 결과와 원고의 문자 구간을 비교하며, 현재 위치 근처를 우선 추적하고 고유한 긴 문구는 원고 전체에서 다시 찾습니다. 원고 외 발화는 위치를 유지합니다. 마이크 권한 거부·장치 오류는 재시도를 중단하고, 일시적 종료는 지연을 두고 재시작합니다. 실제 음향·발음에 따른 현장 리허설이 필요합니다.

## 개발 및 검증

- 기존 PROM 파일은 변경하지 않습니다.
- `vendor.js`: 기존 PROM에 포함된 JSZip 3.10.1(MIT) 및 SheetJS CFB(Apache-2.0) 복사본. 원본 라이선스 안내를 유지합니다.
- `hwp-reader.js`: 기존 PROM HWP 5 파서를 분리해 문단을 원고 줄로 사용합니다.
- `core.js`: 자막 연결과 음성 위치 매칭. `node ppt/tests/core.cjs`로 단위 검증합니다.
- `importers.js`: HWP 계열 및 OOXML 읽기.
- `render.js`: 조작 미리보기와 별도 송출창이 공유하는 슬라이드 표시.
- 실제 첨부 HWP/PPTX(원고 311줄, 자막 40장)로 38장 정확 연결, 1장 확인 필요, 1장 미연결을 확인했습니다. 원본 파일이나 내용은 저장소에 포함하지 않습니다.
- 실제 브라우저에서 파일 업로드, 두 창 송출, 자막/녹색 전환, 모의 음성 이벤트, 수동 제어, IndexedDB 복원을 검증했습니다. 실제 마이크 음향 인식은 현장에서 확인해야 합니다.

## 화면 구성

- 원고의 연결된 자막 부분은 앞뒤 내용과 별도 줄로 나누고 노란색으로 구분합니다. 원고 연결은 문자 위치를 유지하며 화면에 표시된 줄 번호로 수동 연결합니다.
- 오른쪽은 PROM 조작창처럼 여러 장 보기가 기본입니다. 카드 크기(60~180%)에 따라 열 수가 바뀌며, 현재 장 찾기와 한 장 보기를 지원합니다. 송출 중인 카드는 테두리와 배지로 강조합니다.
- 가운데 경계를 드래그하거나 방향키로 조절할 수 있습니다. 기본 원고 폭은 50%이며 조절한 폭은 이 기기에 저장합니다.
- 송출은 1920×1080(16:9) 화면을 기준으로 사용합니다. 다른 비율에서는 화면 전체에 맞춰 가로·세로를 각각 조절하여 추가 여백이 생기지 않습니다.

## PPT 텍스트 서식

마루 부리 보통·굵은 웹폰트는 NAVER 공식 배포 주소에서 불러옵니다(`fonts/LICENSE.txt`). 원본의 한글 글꼴 이름을 해당 실제 글꼴 파일로 연결하며 브라우저 가상 굵기를 사용하지 않습니다. 슬라이드·레이아웃·마스터 서식을 속성별로 상속하고, 글자 크기, 자간, 문단 앞뒤 간격, 줄간격, 여백, 들여쓰기, 세로 정렬 및 저장된 자동 축소 비율을 반영합니다. 공백·탭·강제 줄바꿈을 보존합니다.

기존에 저장한 작업은 가져오기 단계에서 누락된 서식을 복원할 수 없으므로 PPTX를 한 번 다시 불러와야 합니다. 웹폰트를 처음 불러올 때 인터넷 연결이 필요합니다. 다른 글꼴은 해당 기기에 설치되어 있어야 합니다. HTML과 PowerPoint의 글자 배치 엔진이 달라 모든 PPT의 픽셀 단위 동일성을 보장하지는 않습니다.

회귀 검증: 로컬 HTTP 서버에서 `ppt/tests/fidelity.html`을 열면 서식 상속, 빈 기본 서식, 명시적 굵기 해제, 좌표, 자동 축소, 공백, 줄바꿈, 웹폰트 로드를 확인합니다. 실제 40장 원본으로 글꼴 로드와 텍스트 상자 잘림 여부를 추가 확인했습니다.

## 송출 영역 보호

전체 화면용 배경 그림과 PPT 배경 이미지는 화면 가장자리까지 채웁니다. 글자 상자는 원래 위치를 유지하고, 웹폰트 로드 후 실제 줄 크기를 다시 측정하여 넘치는 경우에만 내용 전체를 비례 축소합니다. 이미 들어가는 자막의 글자 크기는 유지합니다.

조작 버튼과 설교 전문은 왼쪽, 자막 여러 장 보기는 오른쪽 맨 위부터 표시합니다. 크기 슬라이더·숫자 입력 및 ‘3줄 맞춤’으로 조절할 수 있습니다. 100%에서는 화면 높이에 최소 세 줄의 카드가 들어가는 크기를 계산합니다.


## 각자 Google Drive에 저장

조작창의 구글 로그인 → 자기 계정 선택 → 앱 파일 접근 허용 → 드라이브 저장/내 자료.
최초 운영자는 [Google 설정 안내](google-setup.html)를 따라 `drive-config.js`의 공개 웹 클라이언트 ID를 설정해야 합니다. 빈 상태에서는 준비 안내만 표시되며 로그인은 실행하지 않습니다. 보안 비밀번호는 사용하지 않습니다.

- `drive.file`만 요청하며 앱에서 만든 작업을 나열합니다. 파일을 공유하거나 운영자 저장소에 업로드하지 않습니다.
- 저장할 때마다 `.prom-ppt.json` 새 파일 생성. 원본(파일당 50MB 이하), 파싱된 화면, 원고, 자막 연결 포함. 전체 작업은 160MB 이하.
- 과거 작업은 원본이 포함되지 않을 수 있으므로 원본까지 보관하려면 한 번 다시 선택합니다.
- OAuth 연결은 만료 시간까지 세션 저장소에서 유지하며, PROM·PPT·Make 이동·새로고침·열린 탭에서 공유합니다. 계정 변경과 로그아웃도 함께 반영합니다. 영구 localStorage에는 토큰을 저장하지 않습니다. 만료·401 거절 시 재로그인이 필요하며, 로그아웃은 기기 작업이나 Google 접근 허용을 삭제하지 않습니다.
- 전체 자료는 기본적으로 기기에 자동 저장되므로 공용 PC 사용 후 사이트 데이터 삭제 필요. 자세한 내용은 [데이터 안내](privacy.html).
- 실제 운영자 클라이언트 ID와 계정으로 로그인/저장/열기 최종 검증이 필요합니다. 모의 OAuth/API 검증은 실제 Google 동의 화면의 검증을 대신하지 않습니다.

## 원고에서 자막 생성·편집

‘자막 PPT 만들기’는 주일·수요·새벽 모두 번호가 붙은 항목만 사용합니다. 번호 없는 설교 전문은 제외하고, 한 항목이 길면 템플릿의 항목 레이아웃으로 이어 만듭니다. 원고 전체·붙여넣은 글을 자동으로 두 줄 자막으로 바꾸는 규칙은 없습니다. 예배 전반 방식은 원고 앞부분의 제목·성경본문만 원본 PPT의 해당 자리에 교체하고, 교독문·광고 등 나머지 순서는 원본 내용이므로 송출 전 확인해야 합니다.

각 카드의 ‘편집’에서 문구·줄바꿈·부분 색상, 레이아웃, 글꼴·크기·굵기·정렬·위치를 수정하고 오른쪽 미리보기로 확인합니다. 추가·삭제·복제·순서 변경을 지원합니다. ‘누적 공개’는 줄바꿈한 문장을 순서대로 공개하는 여러 장으로 만듭니다. 생성 자막은 원문 문자 위치에 직접 연결하며, 복제본이나 원고에 없는 새 문구는 수동 송출 또는 연결 설정이 필요합니다.

‘PPTX 다운로드’는 수정 가능한 텍스트와 배경 이미지를 내보냅니다. 다시 불러오면 같은 원고에 대한 연결과 편집 정보를 복원합니다. 로컬 작업 저장·자동 저장·기존 드라이브 저장에도 생성 결과와 편집 내용이 포함되며, 반복 배경은 한 번만 저장합니다. 원고 원본은 기존 드라이브 저장 방식대로 함께 보관됩니다.

HWP/HWPX/DOCX의 직접 지정된 글자 색을 사용합니다. 복잡한 상속 스타일이나 문서 안의 사진·동영상은 자동 자막 생성에 포함하지 않습니다. 설치되지 않은 템플릿 글꼴은 대체될 수 있으며 PPTX의 줄바꿈은 PowerPoint의 글꼴 환경에 따라 달라질 수 있습니다. 송출 전 미리보기와 원고 연결을 확인하세요.

추가 검증: `/ppt/tests/builder.html`에서 HWPX 색상·부분 강조·성구 분류·원문 연결 및 템플릿을 확인할 수 있습니다. 실제 HWP에서 83장 생성, 웹 편집, PPTX 재열기, IndexedDB 저장, 드라이브 API 모의 저장을 검증했습니다. 내보낸 PPTX는 LibreOffice로 열어 PDF 변환을 확인했습니다.

## 템플릿 서식과 화자 자동 배경

새 자막은 원본 템플릿의 글꼴·크기·좌표·여백을 사용하고 본문 줄간격을 1.3배로 설정합니다. 글자 수 고정 제한 대신 실제 글꼴의 렌더링 너비로 줄바꿈합니다. 번호 항목은 항목 레이아웃의 글상자에 맞춰 나누며, 번호 없는 원고를 하단 자막으로 생성하지 않습니다.

기존 슬라이드를 직접 편집할 때의 화자 배경·성구 레이아웃은 유지됩니다. 새 원고로 자동 제작할 때에는 번호 항목 / 예배 전반 범위를 먼저 적용합니다.

기존 생성 자막은 ‘원본 서식 적용’으로 글꼴·크기·위치·1.3배 줄간격·배경을 일괄 갱신할 수 있습니다. 직접 가져온 PPT의 서식은 유지합니다. 기존 줄바꿈까지 새로 계산하려면 원고에서 다시 생성하세요.

## 부드러운 스크롤·제작 지침 템플릿 (2026-10-17)

스크롤 슬라이드쇼와 설교 전문 따라가기는 한 애니메이션의 목표 위치를 갱신하여 연속 음성 결과에서도 부드럽게 이동합니다. 사용자가 휠·터치로 움직이면 현재 자동 이동은 멈춥니다. 운영체제의 동작 줄이기 설정에서는 즉시 이동/전환합니다.

자막 PPT 만들기의 **제작 지침 템플릿**에서 이름을 입력하고 **현재 설정·지침 템플릿 저장**을 누릅니다. 표지 제목·날짜, 화자 기본 배경, 누적 공개, 제작 범위(번호 항목 / 예배 전반), 전체 제작 지침·추가 메모와 디자인 레이아웃·테마를 함께 저장합니다. 다음 제작에서는 목록에서 선택하면 복원됩니다. 이름을 바꾸어 저장하면 새 템플릿으로 보관됩니다.

### 레이아웃 마스터 편집
자막을 선택한 뒤 **레이아웃 마스터 편집**을 누르면 같은 레이아웃의 적용 장수를 확인할 수 있습니다. 생성 자막은 레이아웃 종류로, 기존 PPT 자막은 배경·요소 배치가 같은 디자인으로 묶습니다. 글상자와 그림·장식의 위치·크기, 글자 서식·줄간격을 편집하고 적용하면 해당 레이아웃 전체가 바뀝니다. 각 장의 문구, 부분 강조색, 원고 연결은 유지합니다.

왼쪽·위쪽은 -100~200%, 너비·높이는 1~300% 범위입니다. 예를 들어 왼쪽 -5%, 너비 110%는 양옆으로 넓힌 배치입니다. 화면 밖 부분은 잘려 보입니다. 그림·장식도 같은 방법으로 넓힐 수 있습니다. 마스터 설정은 작업 파일·PPTX에 저장되며, 생성 레이아웃은 이후 새 자막과 제작 템플릿에도 이어집니다.

## 자막 구간 자동 인식 (2026-10-21)

## 수동 송출 키보드 (2026-10-21)

## 원고·완성 PPT 템플릿의 동일 원고 재현 (2026-10-21)

설교 원고와 완성 PPT로 등록하는 템플릿은 레이아웃 대표 서식과 별도로 원본 장별 구성을 유지합니다. 다음 제작에서 원고의 전체 글자·문장부호·줄과 색상이 같으면 원본 PPT의 각 장을 원래 순서로 재현합니다. 장마다 다른 글꼴·크기·좌표·배경·줄바꿈·누적 공개가 유지되고, 고정 슬라이드는 선택한 위치에 한 번만 들어갑니다. 다운로드와 방송용 PPT 전환에서도 원본 슬라이드 크기를 유지합니다. 명시적으로 학습에서 제외한 본문이나 해제한 고정 장은 제외됩니다.

내용 또는 색상이 다른 원고에는 예전 문구를 재사용하지 않습니다. 새 원고를 저장된 디자인으로 다시 나누며, 학습한 줄간격·여백·자간과 공통 장식을 유지합니다. 표지 제목·날짜를 별도로 입력하면 그 입력을 우선하는 일반 생성 경로를 사용합니다. 템플릿 마스터에서 직접 바꾼 본문 서식과 그림·공통 글자는 동일 원고 재현에도 반영합니다. 예배 전반 모드는 기존 제목·성경본문 교체 규칙을 유지합니다.

기존에 저장한 원고-PPT 템플릿에도 두 원본이 포함되어 있으면 제작 시 원고 식별 정보를 보완합니다. 새로 만든 템플릿·작업·드라이브 파일은 그 정보를 함께 보관합니다.

PowerPoint와 브라우저 간 글꼴/배치 엔진 차이에 관한 제한은 원본 가져오기와 같습니다.


## Make·PPT 공통 생성 엔진 (2026-10-21)

생성 정책은 `make/engine.js`의 `MakePptEngine.generate` 한 곳에서 실행합니다. Make의 만들기 화면과 방송용 PPT의 만들기 창은 원고·템플릿·입력값만 전달합니다. 동일 원고 원본 재현, 일반 원고 자동 생성, 예배 전반 교체, 고정 장 삽입과 출력 크기를 이 엔진에서 결정합니다. 고정 장은 한 번만 삽입하며, PPT에 열려 있던 다른 작업의 임시 마스터 수정이 선택한 템플릿에 섞이지 않습니다.

Make 마스터의 글자 크기 표시·입력도 PowerPoint와 같은 pt 단위를 사용합니다. 23pt는 내부 30.6667px에 해당하며, 원본 재현의 다운로드 크기를 유지하여 46pt로 커지지 않습니다. 글꼴·색만 편집할 때는 기존 고정/비율 줄간격과 줄간격 보정값을 유지합니다.

실제 동일 원고의 원본 재현 57장과 신규 생성 30장에 대해 Make·PPT 양쪽의 장수·본문·서식·배치·원고 연결·출력 크기를 비교합니다. 임시 마스터가 남은 PPT에서도 결과가 같은지 함께 검증합니다.


## 설교 HWP + 광고 붙여넣기 (2026-10-21)

Make의 `광고 복사·붙여넣기`와 방송용 PPT 만들기 창의 같은 입력칸은 설교 원고와 별도로 처리합니다. `1.`, `2.` 또는 `1)` 등으로 시작하는 광고를 항목별로 나눠, 등록한 원고-PPT 템플릿에 포함된 광고 화면만 교체합니다. 광고 표지·마지막 화면·설교 슬라이드·원고 연결은 유지합니다. 같은 HWP의 장별 원본 재현 판정에도 광고는 합치지 않습니다. 비워 두면 기존 광고를 유지합니다.

광고의 그림·글상자 좌표·글꼴·크기·색상·줄간격을 원본 장에서 가져옵니다. 같은 문구는 원본 문단과 부분 서식을 그대로 사용하고, 바뀐 문구는 해당 광고 글상자에 넣습니다. 광고 수가 늘면 마지막 광고 틀을 재사용하며, 줄이 넘치면 원본 글자 크기로 다음 장에 이어 넣습니다. 광고 화면이 없는 템플릿에서는 임의의 설교 레이아웃으로 광고를 만들지 않고 등록 안내를 표시합니다.

광고는 수동 송출 대상으로 남고 설교 음성 추적에 연결하지 않습니다. Make→방송용 PPT 전환·기기 저장·드라이브 작업 저장·PPTX 다시 열기에 붙여넣은 광고 내용을 보관합니다. 공통 Make 엔진의 `make/announcements.js`가 양쪽의 교체를 담당합니다.

검증: `node ppt/tests/announcements.cjs`; `ppt/tests/announcements_browser.cjs`에 개인 원본 경로를 `REG_TEMPLATE`, `REG_SCRIPT`, `AD_FILE`로 전달합니다. 실제 원고와 광고 5개로 57장 생성, 광고 외 장별 원본 동일성, 광고 배경·좌표·폰트·크기·문구, 여백 넘침 없음, PPTX 재열기와 입력 보관, Make→PPT 전환·새로고침 후 동일 재생성을 확인합니다. 원본 원고·이름·광고 자료는 테스트에 포함하지 않습니다.

PPTX에 보관하는 템플릿·마스터의 그림이 슬라이드 그림과 같으면 같은 ZIP 미디어를 참조하고 재열기 때 복원합니다. 제공된 완성 파일은 약 59MB에서 28MB로 줄었고, 50MB 업로드 제한 안에서 다시 열 수 있습니다. 원본 두 파일과 재현 정보는 유지합니다.


## 광고 양식을 포함하는 템플릿 파일 v2 (2026-10-21)

템플릿의 `templateSchemaVersion: 2`, `announcementTemplate.version: 1`에 광고별 이름·고정 화면 번호·본문 요소 식별자·원본 화면 식별자를 저장합니다. 실제 디자인은 기존 고정 화면에 한 번만 보관합니다. 원본과 위치·그림·문구가 달라져도 저장된 연결을 따라 광고를 교체하며, 광고 입력을 비워도 저장한 광고 디자인을 적용합니다. 기존 템플릿은 읽을 때 광고 양식을 인식하고, 저장·파일 내보내기·드라이브 저장에 새 정보를 포함합니다.

③ 마스터 편집의 레이아웃 목록에서 광고 1~5를 각각 고를 수 있습니다. 그림 교체·요소 추가·순서·폰트·pt 크기·위치를 바꾸고 저장하면 다음 광고 제작에 적용됩니다. 본문은 요소 식별자로 연결하므로 도형 순서를 바꿔도 유지하며, 본문을 삭제한 손상 파일은 조용히 다른 글상자를 사용하지 않고 안내합니다. 마스터 저장과 파일 가져오기를 반복해도 광고 화면을 중복 저장하지 않습니다. 방송용 PPT에서 명시적으로 템플릿 저장 시 광고 마스터 수정도 함께 반영합니다.

`announcements.cjs`는 원본과 다른 그림·폰트·좌표·폭·도형 순서로 바꾼 v2 파일의 JSON 재열기를, `announcement_template_browser.cjs`는 실제 마스터 UI 편집→저장→파일 내보내기→새로고침→같은 HWP와 광고 생성의 적용 결과를 확인합니다. 개인 자료는 `REG_TEMPLATE`, `REG_SCRIPT`, `AD_FILE`로 전달합니다.


### 공통 생성 자막 페이지 분할 규칙 (2026-10-22)

- 자동 생성하는 전체 화면 말씀·잠언·성령말씀의 문장/줄바꿈은 실제 글꼴 폭, 문맥상 연결 관계를 고려합니다.
- 문단의 여러 줄을 페이지로 나눌 때 최대 표시 줄 수를 유지하며 문장 종료(. ? !), 쉼표, 연결어미 등 의미상 자연스러운 위치를 우선합니다. 페이지별 줄 수를 균형 있게 배분하고 6+1처럼 마지막 1줄이 홀로 남는 경우를 강하게 억제합니다. 항상 정확히 반으로 나누는 것은 아닙니다.
- 성령말씀은 빈 줄을 새 문단·새 화면 시작점으로 취급하며, 한 줄씩 공개 또는 완성 페이지 출력 옵션을 유지합니다.
- 하단 2줄 자막은 기존 제한을 유지합니다. 원본 PPT 동일 재현, 예배 전반의 고정 순서, 광고·표지·고정 화면은 자동 분할 대상이 아니므로 원본 구조를 유지합니다.
- 템플릿의 지침 글은 사용자에게 규칙을 설명하는 메타데이터이고, 실제 제작은 `ppt/builder.js`와 `make/engine.js` 코드가 수행합니다. 임의의 자유 텍스트 지침만 수정한다고 생성 알고리즘이 바뀌지는 않습니다.

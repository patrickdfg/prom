# OBS 전체화면 전환 · 1.4.2

1.4.1은 OBS와 무관한 창을 제목으로 먼저 제외해 프로그램 정보 조회를 줄이고, 전환 후 중복 상태 확인을 제거합니다. 창 제목과 트레이에도 실행 버전을 표시합니다. 같은 PC에서 창 탐색을 6회 측정했을 때 1.4.0은 396~420ms, 수정본은 최초 68ms·이후 20~25ms였습니다. 이 수치는 창 탐색 시간이며 화면 렌더링 시간은 아닙니다.

1.4.1 실사용에서는 Tab이 수신되는데도 매번 OBS를 뒤로만 보내는 오류가 재현됐습니다. 숨김 창을 포함한 z-order 탐색이 512개에서 끝나 실제로 560번째에 있던 PPT를 놓쳤습니다. 1.4.2는 개수 제한 대신 끝 또는 순환 여부로 탐색을 종료합니다. 600개 창, 560번째 PPT, 앞쪽 가림 창, 가림 창 없음, 순환·빈 목록을 회귀 시험에 추가했습니다.

검증 상태: 빌드, 창 선택·단축키·HTTP 회귀 시험, 웹 연결·원고 표식 시험 통과. 실제 동일 창 순서에서 1.4.1의 잘못된 앞 상태와 1.4.2의 올바른 뒤 상태를 확인했습니다. 수정본 탐색은 최초 26ms, 이후 9~14ms였습니다. 실제 Tab 반복 전환 후 PowerPoint/Chrome 다음 장 이동은 사용자 확인 대기 중이며, 공개 다운로드는 아직 1.4.0입니다.

Windows 10/11에서 `obsscreen.exe`를 더블클릭합니다. PowerShell 실행이나 설치 과정은 필요 없습니다. 기존 버전이나 PowerShell 보조 프로그램을 켜 두었다면 먼저 종료합니다.

프롬프터의 **더보기 → OBS풀스크린설정**에서 [obsscreen 1.4 다운로드](https://patrickdfg.github.io/prom/downloads/OBSFullscreenBridge-1.4.0.exe)를 받을 수 있습니다. 다운로드된 이름은 `obsscreen.exe`입니다.

OBS의 **전체화면 프로젝터**(프로그램 또는 미리보기)를 하나 열고 PowerPoint 전체화면 또는 Chrome 슬라이드쇼와 같은 모니터에 배치합니다. 아래 발표 화면이 PowerPoint인지 Chrome인지 따로 고를 필요가 없습니다. 프로그램은 OBS 프로세스의 프로젝터 제목과 모니터 전체 크기를 확인하여 대상 창을 선택합니다. OBS 편집창과 작은 프로젝터 창은 제외하고, 전체화면 프로젝터가 여러 개이면 임의로 선택하지 않습니다.

- **Tab**: OBS 전체화면이 보이면 맨 뒤로 보내 PowerPoint/Chrome 화면을 표시하고, 가려져 있으면 맨 앞으로 가져옵니다. OBS 창 순서만 바꾸므로 PowerPoint·Chrome의 입력 초점은 그대로 유지됩니다. 작은 알림창이나 obsscreen 상태창이 떠 있어도 OBS의 앞·뒤 상태를 잘못 판단하지 않습니다.
- **토글 단축키 사용**: 기본은 Tab입니다. PgDn·방향키·스페이스는 보조 프로그램이 가로채지 않으므로 PowerPoint 또는 Chrome의 다음 장 이동에 그대로 사용합니다.
- **전체화면 앞으로 / 전체화면 뒤로**: 직접 전환하는 시험 버튼입니다.
- **토글키 설정…**: 버튼을 누른 뒤 원하는 키(예: F8, Ctrl+F8)를 누르고 **저장**합니다. 기본 Tab 대신 새 키로 OBS 전체화면을 앞/뒤 토글합니다. 기존 키의 등록은 해제되며 토글키는 하나만 사용합니다. **설정 해제**로 지울 수 있습니다. 설정은 이 PC에 저장되어 다음 실행에도 유지됩니다. 다른 프로그램과 충돌하면 이전 토글키를 유지하며 알립니다.
- 상태 창의 X나 **트레이로 숨기기**는 프로그램을 종료하지 않습니다. 시계 옆 트레이 아이콘을 두 번 클릭하면 상태 창이 열립니다. **프로그램 종료**를 누르면 단축키와 연결이 해제됩니다.

기존 원고 표식 `(영상1 시작)` / `(영상1 끝)` 및 `(영상)` / `(영상끝)`도 그대로 동작합니다. 시작은 OBS 전체화면을 앞으로, 끝은 뒤로 보냅니다. 프로그램은 전체화면 프로젝터 창만 조작하며 PowerPoint·Chrome·조작창의 키보드 초점·위치·크기를 유지합니다. Tab은 OBS 순서만 전환하고 PgDn은 발표 화면의 다음 장 이동에 남겨 둡니다.

웹 연결은 `127.0.0.1:17986`에서만 받으며, 창 전환 요청은 기존 프롬프터 사이트 Origin과 경로를 검사합니다. `/health`는 준비 상태와 OBS 전체화면 표시 상태를 반환합니다. 단축키는 웹 연결 없이도 동작합니다. 실행 중인 프로그램을 다시 열면 기존 상태 창을 표시합니다. 자동 시작은 등록하지 않습니다.

## 빌드 및 검사

Windows .NET Framework 4.x 기본 컴파일러로 빌드합니다. 추가 패키지나 .NET SDK가 필요 없습니다.

```powershell
.\windows-bridge\build.ps1
```

`tests/windows_bridge_tests.cs`를 빌드한 EXE를 참조하여 콘솔 프로그램으로 컴파일한 뒤 실행하면, 모의 창으로 토글/표식 전환/실패 처리와 실제 로컬 HTTP 요청의 Origin 검사/응답을 검증합니다.
